# FSDC-RECOVERY-001 — Recover *existing* FAITH scientific datasets

**Purpose:** stop sourcing new public datasets until the existing OSM, AERMOD/dust, CHIRPS, geospatial QA and FSDC sources are located, checked and connected to TerraCouncil.

## 1. What is actually confirmed from the repository

The existing `src/import_boke_010hi.py` expects:
- `010HI_evidence.json` (schema `010H-I-1`) and `010HJ_spatial_qa.json` (schema `010H-J-QA-1`), generated by an earlier TerraCouncil geospatial experiment;
- a rectangular AOI `[-14.5,10.5,-14.0,11.0]` in EPSG:4326, and linked SHA256 references for **WorldPop, ESA WorldCover and CHIRPS**;
- no spatial QA errors and `READY_FOR_EXPLORATORY_COUNCIL` before export.

**Critical gap:** it currently exports only **WorldPop and WorldCover** into the hackathon local scientific council. The existing CHIRPS source reference does not become a third observation. This is an integration gap, not evidence that CHIRPS never existed.

The public hackathon repository does not itself include the user's private OSM Boké source files or the FSMI AERMOD PM10/PM2.5 run outputs. Their filenames, schema, accuracy and license must be recovered from the original development artifacts before connecting them to this public hackathon application.

## 2. New implemented recovery utility

`src/fsdc_local_recovery.py` is a **local-only**, read-only inventory program. It looks under explicitly supplied roots for:
- TERRA-META-010HI/J evidence/QA JSON;
- OSM/Overpass, routes, buildings, water and mining/agriculture geospatial artifacts;
- FSMI PM10/PM2.5/dust/AERMOD input/output artifacts;
- FEI/CHIRPS, ERA5, hydrology/rainfall files;
- FSDC scientific registries/manifests.

It records file size, modified time, extension, local path and SHA256 for files up to 25 MiB. Larger files are marked HASH_DEFERRED, not falsely checked. It **does not read numeric measurement values, evaluate scientific quality, upload data, share files with Meta, or modify originals.** This repository contains the code only; the private inventory JSON stays on the user's computer.

### Windows PowerShell — one read-only scan

Open the latest GitHub ZIP in VS Code. The command locates the nested actual package, scans the Documents folders and optionally Downloads, then stores a private inventory outside the public GitHub repo.

```powershell
$ErrorActionPreference = "Stop"
$env:PYTHONUTF8 = "1"
$scanner = Get-ChildItem . -Recurse -File -Filter fsdc_local_recovery.py |
    Select-Object -First 1
if (-not $scanner) { throw "FSDC-RECOVERY-001 absent from the extracted repository" }
$root = $scanner.Directory.Parent.FullName
python -X utf8 -m unittest discover -s (Join-Path $root "tests") -p "test_fsdc_recovery_001.py" -v
if ($LASTEXITCODE -ne 0) { throw "Recovery tests failed" }
$private = Join-Path $HOME "Documents\TerraCouncil-Scientific-Inputs"
New-Item -ItemType Directory -Force -Path $private | Out-Null
$stamp = Get-Date -Format "yyyyMMdd-HHmmss"
$out = Join-Path $private ("FSDC-RECOVERY-" + $stamp + ".json")
$roots = @(
    (Join-Path $HOME "Documents"),
    (Join-Path $HOME "Downloads")
) | Where-Object { Test-Path $_ }
$arguments = @("$($scanner.FullName)")
foreach ($folder in $roots) { $arguments += @("--root", $folder) }
$arguments += @("--out", $out)
python -X utf8 @arguments
if ($LASTEXITCODE -ne 0) { throw "Recovery scan failed" }
$report = Get-Content -LiteralPath $out -Raw -Encoding UTF8 | ConvertFrom-Json
$report.categories | Format-List
Write-Host "Matching scientific artifact files: $($report.matched_count)"
Write-Host "Private metadata report saved to: $out"
```

**Privacy:** the report contains local filesystem paths, dates and file hashes. Do not commit it to the public repository. You can paste only the categories and match counts here; avoid uploading proprietary raw scientific datasets or private files without reviewing permissions.

## 3. Evidence readiness next gates

A filename match alone is not scientific evidence. For any recovered dataset:
1. Identify provider, dataset/version, license, geographic and temporal scope.
2. Check real file format, numeric units, geometry CRS, AOI intersection and source-vs-derivative fingerprints.
3. For AERMOD, distinguish calculated concentration from monitoring observations; verify emissions, weather, receptors, version, time averages and QA.
4. For OSM, document extraction timestamp, attribution, incomplete tiles, topology/geometry quality and source limitations.
5. For CHIRPS, locate original precipitation evidence plus QA; do not label as water quality or flood risk by itself.
6. Admit each item into TerraCouncil only after its own FSDC review, with explicit uncertainty. Keep private data outside the public hackathon repo.

## 4. Acceptance criteria for real progress

This checkpoint is **code and inventory automation**, not completed recovered scientific ingestion. It succeeds as actual retrieval only when the user runs the local scan and produces matched, inspectable original files. Scientific integration succeeds later when at least one non-WorldCover/WorldPop dataset passes QA and changes the new question-bound evidence selection. A different Spark/Wonder answer can then be measured in a separately authorized real debate.

No Meta/ElevenLabs requests are performed by this inventory.
